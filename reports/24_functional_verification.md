## 2. Requested scenarios

`test_functional.py` has numbered scenario tests: (1) actuator not in the control path → FAIL;
(2) correct path → PASS with a traceable explanation; (3) above vs below distinguished; (4) powered
but unused part detected; (5) input without a processing stage; (6) processing output not
connected; (7) insufficient metadata → NOT_CHECKABLE, not FAIL; (8) a novel topology with different
parts; (9) reference designs do not regress. The repair-loop integration is covered separately in
`test_functional_repair_loop.py` (a functionally broken but electrically valid design is rejected,
repaired from coded feedback and accepted). Topic tests add MCU polarity from logic rules, driver
requirement from the registry, missing input/output parts, autonomous behaviour needing a
generator, intent-free inference, vocabulary normalisation, a profile (or honest fallback) for every
registry part, rails never traversed, and determinism. Fixtures cover the thermistor type (unknown →
F101, NTC → PASS), a requested part left unused (F009), gate-level logic, and ten live regressions.

## 5. Known limitations (honest boundaries)

* **Intent extraction is AI.** A wrong intent is enforced faithfully. Round 1's distance display
  passed with an intent that never mentioned the sensor; the prompt fix helped in round 2 but is not a
  guarantee. The Function tab shows the intent and interpretation notes; `set_intent` corrects it.
* **Firmware is only what the logic rules say.** A missing rule is NOT_CHECKABLE; rules name parts,
  not pins (F105 covers the ambiguity); `INPUT_PULLUP` is assumed, not checked, when a button to
  ground is read as LOW; there is no floating-input electrical rule yet.
* **Drive strength is an estimate:** F010 uses V/R of pull-ups and per-family `min_drive_ma`; no
  saturation, gate-threshold or supply-capacity analysis.
* **F011** detects loads tied backwards to a rail through passives only.
* Topology and sign only: no levels, hysteresis, timing, gain or frequency.
* Live sample is small (14 generations, one model). The four round-1 misses show that silent
  functional errors are common in single-shot designs, so more prompts per functional class are
  worth running before relying on the PASS rate.
